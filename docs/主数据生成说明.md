## 六、★ 顺带发现的生成器缺陷（**已修复**，2026-10-04 22:30）

`-- ** 源表：` 依赖声明块**会漏表**。

证据：`scripts/MASTER/dwd/02_etl/DWD_PTY_ORG_BASIC_INFO_PTD.sh` 的 SQL 里读了 **11 张**源表，
而依赖声明块只写了 **3 张**。

根因（`tools/generator/base.py::generate_etl`）：
- `_collect_aliases()` 返回 `{别名: info}`，**以别名做键**；
- 多组 `UNION ALL` 时别名会重复使用（每组都从头叫 `A1/A2/A3`）；
- 旧代码 `all_aliases[alias] = info` 只在别名不存在时才写入 ⇒ **只保住了第一组的表**；
- `dep_block` 由此生成 ⇒ 漏掉后续所有组的源表。

同一个 bug 也解释了 `DWD_PROD_PROD_TAIL_PFD.sh` 为什么只声明 4 张表却实际读 6 张。

### 修复方式

改为直接遍历该 sheet 的**全部映射行**收集源表，按**物理表名**去重、保持首次出现顺序
（顺带修掉了「同一张表因中文名不同而重复出现」的问题）：

```python
dep_map = {}
for mr in sheet.mappings:
    t = mr.src_table_name or mr.src_table_alias
    if not t:
        continue
    if t not in dep_map:
        dep_map[t] = mr.src_table_cn or ""
    elif not dep_map[t] and mr.src_table_cn:
        dep_map[t] = mr.src_table_cn
```
