# 数仓代码自动化生成 — 需求文档

| 项 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 日期 | 2026-10-26 |
| 依据 | 现有仓库 `tools/` 实现、`AGENTS.md` 口径、`tools/ds-deploy/README.md` |
| 用途 | 作为「统一自动化生成脚本」的需求基线：逐条可追溯、可验收 |

---

## 1. 背景与目标

现状：仓库已具备完整能力，但入口分散在 **三条管线 + 20 余个 DS 工具脚本**中，操作者需记住
「哪一步用哪个脚本、什么时候必须 `--apply`、哪些目录不可重生成」。存在三类问题：

1. **入口分散**：`tools/main.py`（生成）、`tools/dwd-pipeline.py`（甲方脚本搬移）、
   `tools/dw-pipeline.py`（一体化）、`tools/ds-deploy/*`（部署/校验/排版/调度）四类入口并存。
2. **口径靠记忆**：`--source jf|gen`、MASTER 禁止重生成、T-1 免配依赖等规则散落在文档与代码注释里。
3. **无端到端单命令**：从「调研文档变更」到「DS 跑批可用」需要人工串 5~9 个命令。

**目标**：产出一份可被逐条验收的需求文档，后续据此实现**单一自动化入口脚本**
（暂定 `tools/auto-gen.py`），实现「一条命令、分阶段、可中断、可 dry-run、可回滚」的端到端流水线。

**成功标准**：
- 一次命令完成 ODS/DWD/DWS 三层产物生成 + 血缘 + 依赖配置 + 校验；
- 任一阶段失败即停止，且不产生半成品落盘（dry-run 默认为默认行为）；
- MASTER 层永远不会被生成器覆盖；
- 所有产物可追溯（阶段级报告 + 明确退出码）。

## 2. 范围

### 2.1 范围内

| 编号 | 能力域 |
|---|---|
| S1 | ODS 层生成（解析调研 Excel → DDL / DataX Shell / 数据字典） |
| S2 | DWD 层（甲方脚本搬移 + MAPPING 归属 + DDL） |
| S3 | DWS 层（甲方脚本比对 / gen 生成） |
| S4 | 血缘与依赖（`DWD_lineage.xlsx` / `DWS_lineage.xlsx` / `dep-config-*`） |
| S5 | 校验（`bash -n`、DDL 并入完整性、Hive 编译、DS 来源审计） |
| S6 | 部署（删除 / 重建 / 脚本同步 / 排版 / 调度） |
| S7 | 报告（阶段报告 JSON/Markdown，落 `.dx-tmp/`） |

### 2.2 范围外

- 调研文档、MAPPING 文档本身的**编辑与修复**（含 MAPPING 缺口修复，如 DWS 三张表的未定义别名）。
- 源系统（O32/HSFA/HSZTA…）侧的抽数与数据库变更。
- DS 集群、Hive 集群的安装运维。
- 主数据血缘的**再推导**（MASTER 血缘为手工定稿，不在自动化范围）。

## 3. 角色与使用场景

| 角色 | 关注点 | 典型场景 |
|---|---|---|
| 数仓开发 | 产物正确性 | 调研表更新后重建 ODS 脚本 |
| 数据工程师 | 血缘/依赖正确 | 新增 DWD 表后补齐调度依赖 |
| 运维/实施 | 部署安全 | 重发布 DWD/DWS 工作流、排版 |
| 甲方评审 | 可追溯 | 查看阶段报告、DDL/ETL 对照 |

**核心场景**：`SC-01` 增量变更（只改了几张调研表）；`SC-02` 全量重建；`SC-03` 只改脚本不重建结构；
`SC-04` 灾后重建（DS 定义层丢失）；`SC-05` 仅做校验不做部署。

## 4. 术语

| 术语 | 含义 |
|---|---|
| `jf` 来源 | 脚本取自甲方交付包（`05-脚本/02-脚本/*执行脚本`），管线只做方言修复与搬移 |
| `gen` 来源 | 脚本由生成器（`main.py`）从 MAPPING 重新生成 |
| `dry-run` | 只计算与打印差异，不写盘、不动 DS；**默认行为** |
| `apply` | 真正落盘 / 调 DS API |
| MASTER | 主数据层，脚本/DDL 取甲方交付、血缘手工定稿，**禁止 gen 覆盖** |
| T-1 免配 | 上游按「批次日-1」分区读取 ⇒ 不建调度依赖 |
| `DEFAULT_EMPTY` | 空脚本占位白名单，**当前为空集**（原 SALE_FEER / TAIL / WARN_HIS 已于 2026-10-27 转正）；需要临时占位用 `--empty-tables` |

## 5. 功能需求

优先级：P0 = 必须；P1 = 应当；P2 = 可选。每条给出**现有实现对照**与**验收方式**。

### FR-01 输入发现与校验（P0）

- 自动发现 `01-系统调研文档/` 下所有系统目录，兼容两种命名：
  `序号-中文名_简称` 与 `序号-简称`。
- 系统简称必须经 `SYSTEM_ALIAS_MAP` 标准化（`ZTA/TA→HSZTA`、`LOFTA→HSFTA`、`直销→HSDS`、
  `聚源→JY`、`官网→OFFW`），查找 MAPPING 时按「原名→别名→标准名」顺序尝试。
- 缺失表级/字段级调研 → 跳过该系统并告警，不中断其他系统。
- **现有实现**：`tools/main.py::_discover_systems/_find_survey_files`、
  `tools/utils/sys_extractor.py`、`tools/utils/mapping_finder.py`。
- **验收**：构造缺一个调研文件的目录，命令仍完成其余系统并输出 WARN。

### FR-02 ODS 生成（P0）

- 输出：`scripts/{系统}/ods/01_ddl.sql`、`ddl/*.sql`、`etl_sh/*.sh`、`data_dict/ODS_dict.xlsx`。
- 生成条件：表级 `是否保留 ∈ {是,Y,y,保留}` 且该表至少 1 个字段 `是否入ODS` 留空/是。
- DDL 列数必须等于 ETL `SELECT` 列数（业务列 + `LD_TIME`），否则拒绝产出。
- 增量表（`_PTD`）必须能解析出增量列，解析不到即报错终止该表。
- 表名 = `ODS_{系统}_{源表名}_{PFD|PTD}`，Schema = `ODS_XDAY_{系统}`。
- **现有实现**：`tools/generator/ods.py`（`generate_all_ods_ddl/_ddl_files/_etl`）、
  `tools/utils/table_utils.py::filter_valid_ods_tables/filter_ods_fields`。
- **验收**：单元测试 `test_ods.py` 全绿；任一产出表 `count(列)` 一致。

### FR-03 DWD 脚本搬移与方言修复（P0）

- 从甲方 `01-DWD执行脚本/*.txt` 搬入 `scripts/{系统}/dwd/02_etl/*.sh`，跳过 `_INIT`。
- 方言修复最小集（Hive 4.2）：去 `SET`、三参 `DATE_FORMAT` 改两参、`SYSDATE` 替换、
  子查询补别名、禁止 `CAST` 出现在分区/别名位置等（详见 `docs/功能与规范文档.md` J-28）。
- 必须输出**逐表修复统计**（`STAT_KEYS`：`dedupe_head/safety/date_format3/sysdate/as_date/...`）。
- **现有实现**：`tools/dwd-pipeline.py::convert/fix_date_format3/add_subquery_alias`。
- **验收**：`bash -n` 全部通过；修复统计与上一版基线对比无新增项。

### FR-04 DWD 表归属（P0）

- 默认规则：`DWD_<主题>_…` → 工作流 `DWD_<主题>`（表名前缀唯一决定归属）。
- 例外必须集中在 `WORKFLOW_OVERRIDE`，且以 **`tools/core/dwd_ownership.py` 为唯一来源**
  （`tools/dwd-pipeline.py` 与 `tools/ds-deploy/ds-build-dependent-from-lineage.py` 只做薄委托）。
- 判定口诀：唯一 DWD 上游映射表在哪个主题 ⇒ 该表归入该主题工作流。
- **验收**：`tools/tests/test_project_consistency.py` 校验两处消费方与共享字典一致（差异为 0 即 PASS）。

### FR-05 DDL 生成与合并（P0）

- DWD DDL 取自甲方 `01-DWD建表脚本.sql`（结构核对 `03-物理模型/`），仅做方言清洗。
- 无 MAPPING 的 DWD 表 DDL 落 `scripts/MASTER/dwd/ddl/` 并并入 `01_ddl.sql`。
- 校验：所有 `ddl/*.sql` 必须并入对应系统 `01_ddl.sql`（缺一即 FAIL）。
- **现有实现**：`dwd-pipeline.py::ddl/parse_jf_ddl/sanitize_ddl/verify`；`generator/ddl_common.py`。
- **验收**：`verify` 输出「DDL 完整性 PASS」。

### FR-06 DWS 脚本来源（P0）

- 默认**不覆盖**仓库内已修复版（`_DWS搬移清单.json` 标 `baseline=repaired-current`）；
  仅 `--force-dws-raw` 时用甲方原文覆盖。
- 交付 24 张表（HSFA 7 / HSZTA 8 / O32 9），`DWS_TRAN_MKT_TRAN_PR_STAT_PTD` 排除。
- gen 模式遇 MAPPING 缺口（`DWS_PROD_INFO_PFD` 等 3 张）**默认失败**，需显式放宽才复制。
- **现有实现**：`tools/dw-pipeline.py::stage_dws_from_jf/cmd_scripts`。
- **验收**：默认模式下注入「甲方原文 ≠ 仓库版」的样本，仓库版文件 mtime 与内容不变。

### FR-07 血缘生成（P0）

- 产出：`scripts/{系统}/dwd/lineage/DWD_lineage.xlsx`、`dws/lineage/DWS_lineage.xlsx`；
  另出 `scripts/DWD_依赖关系.xlsx`（7 sheet：引导页 + 依赖明细/汇总/表级血缘/无同名脚本上游/跨组依赖/语法校验/说明）。
- 血缘需区分：同名脚本上游、无同名脚本上游、跨组（跨系统）依赖、子查询展开后的真实上游。
- 工作簿不混层：DWD 工作簿只做 DWD 侧，DWS 工作簿只做 DWS 侧。
- **现有实现**：`generator/lineage.py`、`dwd-pipeline.py::lineage`。
- **验收**：DWS 血缘表级 160 行、依赖 xlsx 可被 `depcfg` 无异常解析。

### FR-08 调度依赖配置（P0）

- 产出 `tools/ds-deploy/dep-config-proscript/*.dep.json`（DWD）、`dep-config-dws`（DWS）。
- 三类边必须**不生成**：配置表（`SCHEDULE_EXCLUDE`）、上游无脚本、T-1 只读前一日；
  分别打印 `不配(配置表排除)/不配(上游无脚本)/不配(只读前一日) N 条`。
- T-1 判定只认字面形态 `PREV_IDIOM_RE`；`${P_BATCH_DT}` 变体归 `prev_alike`，**只报不删**。
- 免配边清单落 `tools/_prev_day_deps.json`（供后续核对，不作为口径）。
- 依赖一律**作业级**（`DEPENDENT_ON_TASK` + `dateValue=today`），不得退化为工作流级或 SHELL 门禁。
- **验收**：对已知 T-1 边样本，`dep.json` 中该上游不出现在 `dependItems`；运行时打印计数 > 0。

### FR-09 部署（P0）

- 顺序强约束：**先删 DWS → 删/重建 DWD（逆拓扑删、正拓扑建）→ 建 DWS（拓扑 `HSFA→O32→ZTA`）→ 排版**。
- 只删 DWD 且 DWS 仍存在 → 必须拒绝（`check_dwd_only_preflight`）。
- DS 拒绝删除被引用工作流 ⇒ 不允许「逐个重建」。
- 部署前必须跑运行态检查（有跑批则中止）。
- 部署后必须复核：工作流 ONLINE、作业级依赖数量、脚本逐字节一致。
- **现有实现**：`tools/dw-pipeline.py::cmd_delete/cmd_deploy`、
  `tools/ds-deploy/ds-deploy-all-dwd.py`、`ds-check-running.py`、`ds-sync-*.py`。
- **验收**：删除顺序日志符合上述约束；DS 回读工作流列表与预期集合一致。

### FR-10 MASTER 保护（P0）

- MASTER 的脚本、DDL、血缘一律**不可由生成器重建**；任何 gen 路径必须显式排除 `scripts/MASTER`。
- 脚本同步对 MASTER 一视同仁推真实脚本；`DEFAULT_EMPTY`（当前空集）内的表不推。
- **验收**：gen 模式运行后，`scripts/MASTER/dwd/02_etl/*` 与 `lineage/DWD_lineage.xlsx`
  的 sha1 与运行前完全一致；不一致即 FAIL。

### FR-11 SQL 编译校验（P1）

- 全量 DDL 建入临时 schema（默认 `dwdxday_syn_chk`），再对 `02_etl/*.sh` 内 SQL 逐条 `EXPLAIN INSERT`。
- 判定必须「探针存在 **且** 探针前输出段无 `Error:`」（禁止只看探针，历史假阳性）。
- 输出 `tools/.dx-tmp/dwd-syntax-check.json`；`--sys` 只过滤 ETL、DDL 恒全量。
- 基线：DDL 全通过；ETL 109/109 全通过（`DEFAULT_EMPTY` 已清空，无预期内缺口）。
- **现有实现**：`tools/ds-deploy/validate-dwd-syntax.py`。

### FR-12 真实执行（P1）

- 按血缘拓扑序执行（Kahn 拓扑 + 前向边最长路径分层），同层互不依赖。
- 执行前 `DROP + CREATE` 重建全部表（生成 DDL 只有 CREATE）。
- 内存闸门：`MemAvailable < 1.6GiB` 时等待；`--exec-par` 默认 1（并发 DAG > 2 会打爆 worker）。
- 执行后行数回采，0 行表单独标注。
- 输出 `tools/.dx-tmp/dwd-etl-run.json`。
- **现有实现**：`tools/ds-deploy/run-dwd-etl-direct.py`。

### FR-13 数据字典（P1）

- 每层出 `{层}_dict.xlsx`，并汇总跨系统跨层 `scripts/数据字典_汇总.xlsx`。
- 汇总字典只在**全量模式**刷新；`--dwd-mapping-dir` 单目录模式不得覆盖汇总。
- **现有实现**：`generator/data_dict.py`。

### FR-14 统一编排入口（P1 · 本次需求的目标产物）

- 单一命令，阶段化执行，阶段可单选、可跳过：

  | 阶段 | 代号 | 内容 | 默认 |
  |---|---|---|---|
  | 0 | `precheck` | 环境/凭据/DS 运行态/输入文件齐备性 | 执行 |
  | 1 | `ingest` | 输入发现与校验（FR-01） | 执行 |
  | 2 | `gen-ods` | ODS 生成（FR-02） | 按 `--layers` |
  | 3 | `gen-dwd` | DWD 搬移/生成 + 归属（FR-03/04/05/10） | 按 `--layers` |
  | 4 | `gen-dws` | DWS 来源处理（FR-06） | 按 `--layers` |
  | 5 | `lineage` | 血缘 + 依赖配置（FR-07/08） | 执行 |
  | 6 | `verify` | 本地校验 + 可选 Hive 编译 + 可选 DS 审计（FR-11） | 执行 |
  | 7 | `deploy` | 部署/同步/排版/调度（FR-09） | 仅 `--deploy` |
  | 8 | `report` | 汇总阶段报告 | 执行 |

- 参数契约：`--stage`（可累加/`all`）、`--layers`、`--source jf|gen`、`--sys`、`--apply`、
  `--deploy`、`--ds`、`--allow-gen-errors`、`--force-dws-raw`、`--keep-going`、`--report PATH`。
- 退出码：`0` 全通过；`2` 输入不合法；`3` 校验失败；`4` 部署失败；`5` 被前置条件阻止（如 DS 正在跑批）。
- **重用而非重写**：各阶段内部调用现有脚本（`main.py` / `dwd-pipeline.py` / `ds-deploy/*`），
  入口只负责编排、参数校验、失败短路与报告汇总。

### FR-15 阶段报告（P1）

- 每阶段输出结构化报告（JSON）+ 汇总 Markdown，落 `tools/.dx-tmp/auto-<日期>-<时分>/`。
- 报告含：阶段名、入参、耗时、产出文件数、警告清单、失败原因、前后对比摘要。
- 报告路径可由 `--report` 指定；`tools/.dx-tmp/` 默认 gitignored。

### FR-16 变更影响分析（P2）

- 输入变更（哪些 xlsx / txt 的 mtime 或 sha1 变化）→ 输出「受影响表/脚本清单」，
  支持只重建受影响对象的增量模式（`SC-01`）。

## 6. 数据与文件契约

### 6.1 输入

| 输入 | 路径 | 必需 | 说明 |
|---|---|---|---|
| 表级调研 | `01-系统调研文档/{系统}/01-表级调研*.xlsx` | ODS 必需 | `是否保留`、`源系统英文名` |
| 字段级调研 | `01-系统调研文档/{系统}/02-字段级调研*.xlsx` | ODS 必需 | `是否入ODS`、`源表名` |
| DWD MAPPING | `04-源与目标映射MAPPING/01-DWD/{编号}-{系统}/` | DWD gen 必需 | 每个 sheet 一张目标表 |
| DWS MAPPING | `04-源与目标映射MAPPING/02-DWS/{系统}_DWS_*.xlsx` | DWS gen 必需 | 文件名含系统（可别名） |
| 甲方 DWD 脚本 | `05-脚本/02-脚本/01-DWD执行脚本/*.txt` | DWD jf 必需 | 跳过 `_INIT` |
| 甲方 DWD 建表 | `05-脚本/01-建表语句/01-DWD建表脚本.sql` | DWD jf 必需 | 结构核对 `03-物理模型/` |
| 甲方 DWS 脚本 | `05-脚本/02-脚本/02-DWS执行脚本/*.txt` | DWS jf 必需 | 25 个，交付 24 张 |

路径基准由 `DW_D_BASE` / `DW_PROJECT_BASE` 覆盖，默认 `/mnt/d`。

### 6.2 输出

```
scripts/{系统}/{ods|dwd|dws}/
  ├── 01_ddl.sql              # 合并 DDL
  ├── ddl/*.sql               # 按表 DDL
  ├── etl_sh/*.sh (ODS) | 02_etl/*.sh (DWD/DWS)
  ├── lineage/{LAYER}_lineage.xlsx
  └── data_dict/{LAYER}_dict.xlsx
scripts/建表语句/*_建表语句.sql
scripts/DWD_依赖关系.xlsx  DWS_依赖关系.xlsx
scripts/数据字典_汇总.xlsx  _DWD搬移清单.json  _DWS搬移清单.json
tools/ds-deploy/dep-config-proscript/*.dep.json   (DWD)
tools/ds-deploy/dep-config-dws/*.dep.json         (DWS)
tools/.dx-tmp/*.json  （运行报告）
```

### 6.3 写入规范

- 一律 UTF-8 + LF；统一走 `table_utils.write_file / write_file_safe`，禁止裸 `open('w')`。
- 落盘前必须经 `validate_output_path()`（防路径遍历）；系统简称经 `safe_sysname()` 校验。

## 7. 业务规则（不可协商）

| 编号 | 规则 |
|---|---|
| BR-01 | 分区恒为 `PARTITIONED BY (P_DT STRING)`；后缀 `_PFD` 全量 / `_PTD` 增量 |
| BR-02 | ODS 系统字段仅 `LD_TIME`；DWD 为 `SSYS/SRC_TAB/LD_TIME/MODIFY_TIME`；DWS 为 `LD_TIME/MODIFY_TIME` |
| BR-03 | DWD/DWS Schema 固定 `DWDXDAY`/`DWSXDAY`（无系统后缀）；ODS 为 `ODS_XDAY_{系统}` |
| BR-04 | MASTER 禁止 gen 重生成；`DEFAULT_EMPTY`（当前空集）内的表不推真实脚本 |
| BR-05 | 工作流归属按表名前缀；例外只写 `WORKFLOW_OVERRIDE`（单一来源 `tools/core/dwd_ownership.py`） |
| BR-06 | T-1 只读前一日 ⇒ 不配依赖；`${P_BATCH_DT}` 变体只报不删 |
| BR-07 | 依赖一律作业级；不得使用工作流级或 SHELL 门禁替代 |
| BR-08 | 部署顺序：删 DWS → 重建 DWD → 建 DWS → 排版；DS 跑批期间禁止任何变更 |
| BR-09 | DWD 工作流重启顺序：`CMM → PTY → SCR → CHNL → PROD → ACCT → AGMT → AST → EVT → TRAN` |
| BR-10 | DWS 拓扑序：`DWS_HSFA → DWS_O32 → DWS_ZTA` |
| BR-11 | dry-run 为默认；写盘/动 DS 必须显式 `--apply` |
| BR-12 | 源码内不得出现任何口令字面量；凭据仅由 `ds_config.require_secret()` 读取 |
| BR-13 | 文档只记决策与规则，不记一次性运行结果；过程材料只落 `.dx-tmp/` |

## 9. 目标脚本的编排模型（实现约束）

```
auto-gen.py
 ├─ precheck   : 环境变量/凭据/目录存在性/DS 运行态/Hive 可达（可 --skip-hive）
 ├─ ingest     : 发现系统 → 校验输入齐备 → 生成 run-id
 ├─ gen-ods    : main.py --layer ODS   （按 --sys 过滤）
 ├─ gen-dwd    : jf → dwd-pipeline convert/distribute/ddl + MASTER 保护检查
 │               gen → main.py --layer DWD（显式排除 MASTER）
 ├─ gen-dws    : jf → stage_dws_from_jf（默认不覆盖） / gen → main.py --layer DWS
 ├─ lineage    : dwd-pipeline lineage + depcfg；DWS 侧 ds-build-dws-dependent-from-lineage
 ├─ verify     : verify + bash -n + [--hive] validate-dwd-syntax + [--ds] 来源审计
 ├─ deploy     : [--deploy] ds-check-running → dw-pipeline deploy → relayout → schedule
 └─ report     : 汇总 JSON/Markdown → .dx-tmp/auto-<ts>/
```

**实现约束**：
1. 各阶段复用现有脚本，不复制其业务逻辑；调用方式统一为子进程 + 明确退出码解析。
2. 阶段间通过 `run-id` 目录传递中间产物，避免全局状态（现有脚本里的模块级全局变量不可继承）。
3. 阶段前置条件不满足 → 直接跳过并记录 `SKIPPED`（不算失败，但报告中标注）。
4. gen 模式必须内置 MASTER sha1 前后比对（FR-10）。

## 10. 风险与约束

| 风险 | 影响 | 应对 |
|---|---|---|
| MAPPING 质量缺口（3 张 DWS 表未定义别名、括号不平衡） | gen 模式产出非法 SQL | gen-DWS 默认失败；需修 MAPPING 才放开 |
| DS 跑批与部署冲突 | 数据错乱 / 任务失败 | `precheck` 强制 `ds-check-running`，非空闲即中止 |
| DS 会话互踢（同 user 单会话） | 401 失败 | 全程串行，禁止并发调 DS |
| 临时表族（如 SALE_FEER / WARN_HIS / TAIL） | 依赖边占位但无数据 | 已于 2026-10-27 转正跑真实脚本；再出现同类缺口时用 `--empty-tables` 占位保边 |
| 重建换 code | 旧依赖失效 | 强制「先全删再正拓扑重建」 |
| 路径双环境差异 | 误报缺文件 | 统一探测回退 + `DW_*` 环境变量 |
