## 2. P0 — 严重问题（必须修复）

### 2.1 `fields[0]` 越界风险

- **位置：** [tools/generator/ods.py:108](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/ods.py#L108)
- **现象：** `generate_ods_etl()` 中直接取 `fields[0].src_name`：
  ```python
  select_parts = [f"SELECT  {fields[0].src_name}"]
  ```
- **风险：** 若 `fields` 为空列表会抛 `IndexError`，导致整个 ODS 生成流程崩溃。
- **修复：** 在函数入口增加空列表保护：
  ```python
  if not fields:
      logger.warning(f"  表 {table.ods_table} 无字段，跳过 ETL 生成")
      return ""
  ```
- **关联：** 虽然 `iter_ods_tables()` 已过滤无字段表，但 `generate_ods_etl()` 作为公共 API 仍应自我防御。

### 2.2 类型映射文档与代码不一致

- **位置：** [tools/core/type_mapper.py:35](file:///c:/Users/k't/Documents/trae_projects/dw/tools/core/type_mapper.py#L35)
- **现象：**
  - 代码：`FLOAT` / `BINARY_FLOAT` / `BINARY_DOUBLE` → `DECIMAL(18,2)`
  - 文档（[docs/规范文档.md:746-747](file:///c:/Users/k't/Documents/trae_projects/dw/docs/规范文档.md#L746-L747)）：→ `DECIMAL(30,8)`
- **风险：** 业务方按文档设计精度，实际生成精度不足，可能截断数据。
- **修复：** 统一为 `DECIMAL(30,8)`（与文档一致，更安全），并补充单元测试锁定。

### 2.3 缺少 `requirements.txt`

- **位置：** 项目根目录
- **现象：** [docs/规范文档.md:70](file:///c:/Users/k't/Documents/trae_projects/dw/docs/规范文档.md#L70) 提到 `requirements.txt` 存在，但实际缺失。
- **风险：** 其他开发者无法复现环境，CI/CD 无法自动化。
- **修复：** 创建 `requirements.txt`：
  ```
  pandas>=1.3.0
  openpyxl>=3.0.0
  ```
  并补充 `python_requires` 信息。

## 3. P1 — 重要优化（高收益）

### 3.1 DDL 生成逻辑重复

- **位置：**
  - ODS：[tools/generator/ods.py:18-35](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/ods.py#L18-L35)
  - DWD/DWS：[tools/generator/base.py:45-78](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/base.py#L45-L78)
- **现象：** 两处字段定义构建逻辑高度重复（验证标识符 → 拼接字段行 → 追加系统字段 → 调 `generate_ddl_body`）。
- **优化：** 抽取通用方法到 [tools/generator/ddl_common.py](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/ddl_common.py)：
  ```python
  def build_field_defs(field_specs, sys_fields=None, existing_names=None):
      """统一的字段定义构建器"""
  ```
- **收益：** 消除约 30 行重复代码，未来调整字段格式只需改一处。

### 3.2 `generate_all_*_files` 模式重复

- **位置：**
  - [tools/generator/ods.py:56-63](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/ods.py#L56-L63)（`generate_all_ods_ddl_files`）
  - [tools/generator/base.py:99-109](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/base.py#L99-L109)（`generate_all_ddl_files`）
- **现象：** 两个"按表生成独立文件"方法结构几乎完全相同：建目录 → 遍历 → 生成内容 → `write_file_safe`。
- **优化：** 抽取 `write_files_per_table(items, output_dir, ext, content_fn)` 通用函数。

### 3.3 Hive SET 配置重复

- **位置：**
  - 集中配置：[tools/config.py:45-60](file:///c:/Users/k't/Documents/trae_projects/dw/tools/config.py#L45-L60) `HIVE_SETTINGS`
  - 硬编码重复：[tools/generator/ods.py:136-141](file:///c:/Users/k't/Documents/trae_projects/dw/tools/generator/ods.py#L136-L141) `dynamic_sets`
- **现象：** `dynamic_sets` 中有 5 条配置与 `HIVE_SETTINGS` 完全相同（动态分区相关）。
- **优化：** 在 `config.py` 中拆分 `HIVE_DYNAMIC_PARTITION_SETTINGS` 常量，两处复用。

### 3.4 硬编码 WSL 路径

- **位置：** [tools/config.py:3-7](file:///c:/Users/k't/Documents/trae_projects/dw/tools/config.py#L3-L7)
- **现象：**
  ```python
  D_BASE = "/mnt/d"  # WSL 专属路径
  PROJECT_BASE = os.path.join(D_BASE, "项目/信达澳亚数仓/...")
  ```
- **风险：** Windows 原生、macOS、Linux 环境均无法直接使用；中文路径在某些工具链下有编码问题。
- **优化：** 支持环境变量覆盖：
  ```python
  D_BASE = os.environ.get("DW_D_BASE", "/mnt/d")
  PROJECT_BASE = os.environ.get("DW_PROJECT_BASE",
      os.path.join(D_BASE, "项目/信达澳亚数仓/信达澳亚投研数据集市交付文档"))
  ```

## 5. P3 — 锦上添花

### 5.1 缺少 `pyproject.toml`

- **位置：** 项目根目录
- **现象：** 无包管理配置，无法 `pip install -e .`。
- **优化：** 创建最小化 `pyproject.toml`，声明项目元数据和依赖。

### 5.2 `mapping.py` 关键词扫描可提前终止

- **位置：** [tools/parser/mapping.py:86-92](file:///c:/Users/k't/Documents/trae_projects/dw/tools/parser/mapping.py#L86-L92)
- **现象：** 关键词扫描遍历整个 DataFrame，找到所有关键词后仍继续。
- **优化：** 在 `keyword_rows` 长度等于 `_KEYWORDS` 长度时 `break`。
- **收益：** 大文件场景下减少无意义遍历。

### 5.3 类型注解不完整

- **位置：** 多处
- **现象：** 大部分函数参数和返回值缺少类型注解，如 `fields: list` 应为 `fields: list[FieldMeta]`。
- **优化：** 逐步补充类型注解，配合 `mypy` 静态检查。

### 5.4 `__pycache__` 可能混入版本控制

- **位置：** 多处 `.pyc` 文件
- **现象：** `.gitignore` 似乎未生效或有历史遗留。
- **优化：** 确认 `.gitignore` 包含 `__pycache__/` 和 `*.pyc`，必要时 `git rm --cached` 清理。

## 7. 回退策略

### 7.1 推荐方案：开新分支

```bash
git checkout -b refactor/optimization
```

- 所有改动在新分支完成，`main` 完全不动
- 出问题直接 `git checkout main` 切回，零风险
- 验证无误后合并

### 7.2 备选方案：分阶段提交

- 每个阶段（P0/P1/P2）独立一个 commit
- 出问题可 `git revert <commit>` 精准回退单步
- 不混合多个改动到一个 commit

### 7.3 安全约定

执行过程中严格遵守：

- ❌ 不使用 `git reset --hard`（会丢工作区改动）
- ❌ 不使用 `git push --force` 到 main
- ❌ 不使用 `--amend` 已推送的提交
- ❌ 不跳过 hooks（`--no-verify`）
- ✅ 每次改完先跑测试再提交
- ✅ 每个阶段提交前人工确认
