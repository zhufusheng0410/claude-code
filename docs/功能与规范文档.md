## 1. 项目概述

### 1.1 项目简介

数仓代码自动生成工具是一个基于 Python 的自动化脚本生成系统，用于从 Excel 调研文档自动生成数据仓库各层代码，包括：

- **ODS 层**：建表 DDL、DataX 抽数脚本（Shell）
- **DWD 层**：建表 DDL、ETL 加工 Shell 脚本、血缘关系、数据字典
- **DWS 层**：建表 DDL、ETL 加工 Shell 脚本、血缘关系、数据字典

### 1.2 技术栈

| 组件 | 技术选型 |
|------|---------|
| **语言** | Python 3.8+ |
| **依赖库** | pandas、openpyxl、dataclasses |
| **目标引擎** | Inceptor (Hive)、DataX、Beeline |
| **目标存储** | HDFS |
| **日志系统** | Python logging 模块 |

## 2. 技术架构

### 2.1 三层架构

```
┌─────────────────────────────────────────┐
│         Parser (解析器层)                │
│  读取 Excel，提取元数据，转换为 IR         │
│  - table_survey.py: 表级调研解析         │
│  - field_survey.py: 字段级调研解析       │
│  - mapping.py: MAPPING 解析              │
│  - sys_extractor.py: 系统名提取          │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│         IR (中间表示层)                  │
│  内存中的结构化数据类                     │
│  - TableMeta: 表元数据                   │
│  - FieldMeta: 字段元数据                 │
│  - MappingRule: 映射规则                 │
│  - MappingSheet: 映射工作表              │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│         Generator (生成器层)             │
│  从 IR 输出 SQL/Shell/Excel 文件          │
│  - ods.py: ODS 层生成器                  │
│  - base.py: DWD/DWS 通用生成器           │
│  - ddl_common.py: DDL 构建工具           │
│  - lineage.py: 血缘关系生成              │
│  - data_dict.py: 数据字典生成            │
└─────────────────────────────────────────┘
```

### 2.2 核心数据类（`tools/core/ir.py`）

```python
@dataclass
class TableMeta:
    """表元数据"""
    src_sys: str              # 源系统英文名（如 "O32"）
    src_db_type: str          # 源数据库类型（如 "ORACLE"）
    src_schema: str           # 源 schema（如 "FMP"）
    src_table: str            # 源表名（如 "TUNITSTOCK"）
    src_table_cn: str         # 源表中文名
    ods_table: str            # ODS 表名
    load_strategy: str        # 加载策略：FULL / INCR
    incr_cond: str            # 增量条件字段名
    incr_cond_format: str     # 增量条件格式（如 yyyyMMdd）
    is_partition: str         # 是否分区
    storage_period: str       # 存储周期
    topic: str                # 主题
    table_rows: str           # 表行数估算
    is_reserved: str          # 是否保留（是/否）

@dataclass
class FieldMeta:
    """字段元数据"""
    src_sys: str              # 源系统英文名
    src_table: str            # 源表名
    src_table_cn: str         # 源表中文名
    ordinal: float            # 字段序号
    src_name: str             # 字段英文名
    src_name_cn: str          # 字段中文名
    src_type: str             # 字段原始类型
    hive_type: str            # 转换后的 Hive 类型
    nullable: str             # 是否允许为空 Y/N
    pk_flag: str              # 是否主键
    biz_pk_flag: str          # 是否业务主键
    fk_flag: str              # 是否外键
    default_val: str          # 默认值
    is_ods: str               # 是否入 ODS
    note: str                 # 备注

@dataclass
class MappingRule:
    """映射规则"""
    tgt_name: str             # 目标字段英文名
    tgt_name_cn: str          # 目标字段中文名
    tgt_type: str             # 目标字段类型（Hive 类型）
    tgt_ordinal: float        # 序号
    is_pk: str                # 是否主键
    group_no: str             # 组别
    src_field_alias: str      # 源字段别名（如 T1.CUST_ID）
    src_table_alias: str      # 源表别名（如 T1）
    src_table_name: str       # 源表名
    src_table_cn: str         # 源表中文名
    src_field_name: str       # 源字段名
    join_type: str            # JOIN 方式（MAIN TABLE / LEFT JOIN / ...）
    join_cond: str            # 关联条件（ON ...）
    filter_cond: str          # 过滤条件
    note: str                 # 备注

@dataclass
class MappingSheet:
    """映射工作表"""
    tgt_table_cn: str         # 目标表中文名
    tgt_table: str            # 目标表名
    func_desc: str            # 功能描述
    partition_col: str        # 分区字段（默认 p_dt）
    param: str                # 参数（默认 p_batch_dt）
    frequency: str            # 频度（默认 D）
    tgt_table_type: str       # 目标表类型
    load_type: str            # 加载类型
    incr_logic: str           # 增量逻辑
    source_tables: [str]      # 源表列表
    mappings: [MappingRule]   # 映射规则列表
```

## 3. 数仓层级规范

### 3.1 层级定义

| 层级 | Schema | 说明 | 分区字段 | 系统字段 |
|------|--------|------|----------|---------|
| ODS | `ODS_XDAY_{系统}` | 操作数据层，保持源系统字段名 | `P_DT` | LD_TIME（2026-09-28 起） |
| DWD | `DWDXDAY` | 明细数据层，按主题建模 | `P_DT` | SSYS, SRC_TAB, LD_TIME, MODIFY_TIME |
| DWS | `DWSXDAY` | 汇总数据层，面向业务主题 | `P_DT` | LD_TIME, MODIFY_TIME |

### 3.2 表名规范

#### 3.2.1 ODS 表名

```
ODS_{系统}_{源表名}_{后缀}
```

| 系统 | 示例表名 | 说明 |
|------|---------|------|
| O32 | `ODS_O32_TUNITSTOCK_PFD` | 全量表 |
| HSZTA | `ODS_HSZTA_SCOMBI_PTD` | 增量表 |
| HSFA | `ODS_HSFA_CUST_INFO_PFD` | 全量表 |
| HSFTA | `ODS_HSFTA_ACCOUNT_PFD` | 全量表 |
| HSDS | `ODS_HSDS_CUSTOMER_PFD` | 全量表 |
| WIND | `ODS_WIND_INDEX_PFD` | 全量表 |
| JY | `ODS_JY_MARKET_PFD` | 全量表 |
| OFFW | `ODS_OFFW_NEWS_PFD` | 全量表 |
| OA | `ODS_OA_APPROVAL_PFD` | 全量表 |

#### 3.2.2 DWD 表名

```
DWD_{主题}_{实体}_{后缀}
```

**示例：**
- `DWD_AST_CRSE_INFO_PFD`（资产 - 课程信息 - 全量）
- `DWD_AST_CUST_HLDP_PTD`（资产 - 客户持仓 - 增量）
- `DWD_PROD_INFO_PFD`（产品 - 信息 - 全量）

#### 3.2.3 DWS 表名

```
DWS_{主题}_{实体}_{后缀}
```

**示例：**
- `DWS_PROD_SCR_HLDP_DETAIL_PTD`（产品 - 筛选持仓明细 - 增量）
- `DWS_TRAN_ACCT_OPEN_BTCH_PFD`（交易 - 账户开户批次 - 全量）
- `DWS_CUST_HOLD_AST_SUM_PFD`（客户 - 持有资产汇总 - 全量）

### 3.3 后缀规则

| 后缀 | 含义 | 说明 |
|------|------|------|
| `_PFD` | Partition Full Data | 全量数据，每日覆盖 |
| `_PTD` | Partition Time-slice Data | 增量数据，按时间切片 |

**判断依据：**
- 加载策略包含"增量" → `_PTD`
- 加载策略为"全量" → `_PFD`

### 3.4 分区规范

**所有层统一使用：**
```sql
PARTITIONED BY (P_DT STRING)
```

**全量表（覆盖写入）：**
```sql
INSERT OVERWRITE TABLE schema.table PARTITION(P_DT='${p_end_dt}') ...
```

**增量表（动态分区）：**
```sql
SET hive.exec.dynamic.partition=true;
SET hive.exec.dynamic.partition.mode=nonstrict;
INSERT OVERWRITE TABLE schema.table PARTITION(P_DT) ...
```

### 3.5 存储格式

```sql
ROW FORMAT DELIMITED FIELDS TERMINATED BY '\t' NULL DEFINED AS '';
```

- `01-表级调研 - 恒生分 TA(HSFTA)_V1.0.xlsx`

#### 4.1.2 文件位置

```
D:/项目/.../01-系统调研文档/
├── 01-恒生投资交易系统_O32/
│   ├── 01-表级调研 - 恒生投资交易系统 (O32)_V1.0.xlsx

│   └── 02-字段级调研 - 恒生主 TA(HSZTA)_V1.0.xlsx
└── ...
```

#### 4.1.3 Sheet 结构

| 行区域 | 内容 | 说明 |
|--------|------|------|
| Row 0-2 | 工作区说明/标题/列头 | 数据从 Row 3 开始 |
| Row 3+ | 数据行 | 每行 = 一张表 |

#### 4.1.4 列定义（0-indexed）

| 列索引 | 列名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| 0 | 源数据库类型 | String | 是 | - | ORACLE |
| 1 | 源系统中文名 | String | 是 | - | 如"恒生投资交易系统" |
| 2 | 源系统英文名 | String | 是 | - | **O32/HSZTA/HSFA/...** |
| 3 | 源系统 schema 名 | String | 是 | - | 如 FMP |
| 4 | 源表英文名 | String | 是 | - | 如 TUNITSTOCK |
| 5 | 源表中文名 (表描述) | String | 是 | - | 如"单位持仓表" |
| 6 | 源表名 | String | 是 | - | 与列 4 相同 |
| 7 | ODS 名称 | String | 否 | 自动生成 | 留空自动用模板生成 |
| 8 | 中文名称 | String | 否 | 源表中文名 | ODS 表中文描述 |
| 9 | 表行数 | String | 否 | 空 | 估算值 |
| 10 | 是否保留 | String | 是 | - | **是/否/保留** |
| 11 | 是否入 ODS | String | 是 | - | 是/否 |
| 12 | 加载方式 | String | 否 | - | - |
| 13 | 频率 | String | 否 | - | 如 D/W/M |
| 14 | 存储周期 | String | 否 | - | 如 T+1 |
| 15 | 是否分区 | String | 否 | - | 是/否 |
| 16 | 分区字段 | String | 否 | - | 如 L_DATE |
| 17 | 增量条件 | String | 否 | - | 增量字段名 |
| 18 | 增量条件格式 | String | 否 | - | 如 yyyyMMdd |
| 19 | 主题 | String | 否 | - | 业务主题 |

## 6. 生成的代码规范

### 6.1 ODS 层代码

#### 6.1.1 DDL 生成

```sql
DROP TABLE IF EXISTS ODS_XDAY_{系统}.ODS_{系统}_{源表}_{后缀};
CREATE TABLE ODS_XDAY_{系统}.ODS_{系统}_{源表}_{后缀} (
   {字段 1}  {Hive 类型} DEFAULT NULL COMMENT '{注释}',
   {字段 2}  {Hive 类型} DEFAULT NULL COMMENT '{注释}'
)
COMMENT '{源表中文名}'
PARTITIONED BY ( P_DT STRING )
ROW FORMAT DELIMITED FIELDS TERMINATED BY '\t' NULL DEFINED AS '' ;
```

**生成逻辑：**
1. 只处理 `is_reserved` 为 `是/保留/Y/y` 的表
2. 只处理 `is_ods` 为 `是/Y/y` 或空值的字段
3. 字段名使用源字段名
4. Hive 类型为字段级调研中定义的转换类型

#### 6.1.2 ETL 生成（DataX Shell 脚本）

**文件结构：**
```bash
#!/bin/sh
source ${hadoop_env}
source ${source_path}

# 1. 创建临时表
beeline -u ${hive_jdbc} -n ${hive_username} -p ${hive_password} -e "
  CREATE TABLE IF NOT EXISTS {schema}.{tmp_table} (
    {字段定义}
  )
  ROW FORMAT DELIMITED FIELDS TERMINATED BY '\001';
"

# 2. DataX 导入 Oracle → HDFS
# (DataX JSON 配置嵌入脚本)

# 3. 插入目标表
INSERT OVERWRITE TABLE {schema}.{target_table} PARTITION(P_DT='${p_end_dt}')
SELECT ...
FROM {schema}.{tmp_table};
```

**ETL 生成逻辑：**
1. 使用 `demo/templates/etl_ods_template.sh` 模板
2. 全量表：`INSERT OVERWRITE ... PARTITION(P_DT='${p_end_dt}')`
3. 增量表：动态分区 `INSERT OVERWRITE ... PARTITION(P_DT)` + 增量条件过滤
4. 字段列表为空时跳过并记录 WARNING

### 6.2 DWD/DWS 层代码

#### 6.2.1 DDL 生成（`tools/generator/base.py`）

**生成逻辑：**
1. 目标字段名去重（防止重复列）
2. 字段按 `tgt_ordinal` 排序
3. 追加系统字段（DWD: SSYS, SRC_TAB, LD_TIME, MODIFY_TIME / DWS: LD_TIME, MODIFY_TIME）
4. 系统字段不重复追加（如果映射中已包含则跳过）

```sql
DROP TABLE IF EXISTS {Schema}.{表名};
CREATE TABLE {Schema}.{表名} (
   {字段1}  {类型} DEFAULT NULL COMMENT '{注释}',
   {字段2}  {类型} DEFAULT NULL COMMENT '{注释}',
   ...
   SSYS  STRING DEFAULT NULL COMMENT '源系统',          -- 仅 DWD
   SRC_TAB  STRING DEFAULT NULL COMMENT '源表',        -- 仅 DWD
   LD_TIME  STRING DEFAULT NULL COMMENT '加载时间',
   MODIFY_TIME  STRING DEFAULT NULL COMMENT '修改时间'
)
COMMENT '{表中文名}'
PARTITIONED BY ( P_DT STRING )
ROW FORMAT DELIMITED FIELDS TERMINATED BY '\t' NULL DEFINED AS '' ;
```

#### 6.2.2 ETL 生成（Shell 脚本）

**文件结构：**
```bash
#!/bin/sh
source ${hadoop_env}
source ${source_path}

inceptor_beeline() {
    beeline -u ${hive_jdbc} -n ${hive_username} -p ${hive_password} -e "$1"
}

inceptor_beeline "

-- ** 主题:{主题}
-- ** 描述:{描述}
-- ** 目标表：{Schema}.{表名}

set hive.exec.dynamic.partition=true;
set hive.exec.dynamic.partition.mode=nonstrict;
set hive.exec.max.dynamic.partitions.pernode=10000;
set hive.exec.max.dynamic.partitions=10000;

INSERT OVERWRITE TABLE {Schema}.{表名} PARTITION(P_DT = '${参数}')
SELECT
       T1.{字段}                     AS {目标字段}                     --{注释}
     , T2.{字段}                     AS {目标字段}                     --{注释}
     , 'O32'                         AS SSYS                          --源系统
     , '表1,表2'                     AS SRC_TAB                       --源表
     , FROM_UNIXTIME(UNIX_TIMESTAMP(CURRENT_TIMESTAMP()),'yyyy-MM-dd HH:mm:ss') AS LD_TIME   --加载时间
     , FROM_UNIXTIME(UNIX_TIMESTAMP(CURRENT_TIMESTAMP()),'yyyy-MM-dd HH:mm:ss') AS MODIFY_TIME --修改时间
FROM {源表1} T1
  LEFT JOIN {源表2} T2 ON T1.{字段} = T2.{字段}
    AND T2.{字段} = '条件'
WHERE 过滤条件1
  AND 过滤条件2
;"
```

**SELECT 子句对齐规则：**
```python
_AS_POS = 80        # " AS 别名" 起始列
_COMMENT_POS = 120  # "--注释" 起始列

# 格式：前缀 + 表达式.ljust(80) + " AS " + 别名.ljust(120 - 80 - len(' AS 别名')) + "--注释"
#    T1.CUST_ID                                                                    AS CUST_ID                        --客户ID
```

**CASE 表达式格式化：**
```sql
 -- 多行 CASE
 , CASE WHEN T1.C_CUSTTYPE IS NOT NULL
        THEN COALESCE(T3.STD_DICT_CLS_CD_VAL,CONCAT('@',T1.C_CUSTTYPE))
    END                                                                          AS CUST_TYPE_CODE                      --客户类型代码
```

  `LD_TIME`，DDL 必须同步追加，否则建表列数比 SELECT 列数少 1，执行报
  `SemanticException [Error 10044]`。

### 9.1 DWD 层系统字段

```python
    ("SSYS", "STRING", "源系统"),
    ("SRC_TAB", "STRING", "源表"),
    ("LD_TIME", "STRING", "加载时间"),
    ("MODIFY_TIME", "STRING", "修改时间"),

```

- **SSYS 生成**：当前系统名称（如 `'O32'`）
- **SRC_TAB 生成**：该 DWD 表涉及的所有源表名，逗号连接（如 `'ODS_O32_TUNITSTOCK_PFD,ODS_O32_TUNITINFO_PFD'`）

### 15.3 工作流归属覆盖与 T-1 免配口径（2026-10-23 用户拍板）

**① 归属：默认按表名前缀，个别表用 `WORKFLOW_OVERRIDE`**

- 默认唯一规则：`DWD_<主题>_…` → 工作流 `DWD_<主题>`，实现见 `tools/core/dwd_ownership.py::own_workflow`。
- 例外只写在 `WORKFLOW_OVERRIDE`，**单一来源 `tools/core/dwd_ownership.py`**（2026-10-29 起）：
  `tools/dwd-pipeline.py`（现役 `depcfg` 生成器）与
  `tools/ds-deploy/ds-build-dependent-from-lineage.py`（旧入口，且被 DWS 构建器复用）
  都只是薄委托，口径变更只改共享模块；守门用例 `tools/tests/test_project_consistency.py`。
- 已定清单（**下次同类照此办理**）：

  | 表 | 原工作流 | 归到 | 理由 |
  |---|---|---|---|
  | `DWD_PTY_OPER_FUND_PRVL_PFD` | `DWD_PTY` | **`DWD_PROD`** | 唯一 DWD 上游 `DWD_PROD_SFAC_NUM_MAPP_PFD` 在 PROD，留在原工作流会形成工作流级环（跨流互等） |
  | `DWD_CMM_INTR_PARA_PFD` | `DWD_CMM` | **`DWD_PROD`** | 同上（上游同为 `DWD_PROD_SFAC_NUM_MAPP_PFD`） |

- 判定口诀：**上游映射表在哪，表就放哪** —— 唯一 DWD 上游是 `DWD_PROD_*NUM_MAPP_*` 的，一律归 `DWD_PROD`。
- 粒度是**表**不是文件：`.sh` 与 DDL 仍留在原系统目录（如 `scripts/O32/dwd/…`），只改 DS 工作流成员与 dep 配置。
- 搬迁方式：改 `tools/core/dwd_ownership.py` 的 `WORKFLOW_OVERRIDE` → `dw-pipeline.py config --layers DWD --apply` 重生成 dep 配置 →
  `dw-pipeline.py deploy --layers DWD,DWS --apply` 全量重建（DWS 需先删以释放引用）。

**② 调度依赖：上游读「前一日分区」（T-1）⇒ 不配依赖**

- 口径原文（**必须是这个字面形态**）：

  ```sql
  DATE_FORMAT(DATE_SUB(TO_DATE(FROM_UNIXTIME(UNIX_TIMESTAMP('${p_end_dt}','yyyyMMdd'))),1),'yyyyMMdd')
  ```

  允许空白/换行任意、`UNIX_TIMESTAMP` 内多包一层 `CAST(… AS STRING)`；`${p_end_dt}` 另有 `${P_BATCH_DT}` 变体（同值同义）。
- 语义：目标表按**批次日-1**分区读上游 ⇒ 当天上游实例没跑也能取到数 ⇒ **不建调度依赖边**，DAG 里不出现，也不产生跨工作流作业级等待。
- 实现：`dwd-pipeline.py::PREV_IDIOM_RE` 只认上述字面形态（**不是「含 `DATE_SUB` 就算」**——周/月/账期偏移会误判）→
  `lineage` 在 `DWD_依赖关系.xlsx`「依赖明细」的「调度依赖」列写 `不配依赖(只读前一日)` →
  `depcfg` 跳过该边；清单落 `tools/_prev_day_deps.json`。
- ⚠ `${P_BATCH_DT}` 变体归 `prev_alike`：**只报不删**，不擅自扩大口径。
- 命中哪些边不写死在本文件（脚本改了就失真）：以 `depcfg` 运行时打印与 `tools/_prev_day_deps.json` 为准。

| 字段类型全是 STRING | 字段级调研中缺少 Oracle 类型 | 补全字段级调研的"字段类型"列 |
| 生成后表名有下划线过多 | 源字段名含空格/特殊字符 | `_sanitize_identifier()` 自动修复 |
| ETL 脚本中 DataX 配置为空 | 模板文件缺失 | 检查 `demo/templates/etl_ods_template.sh` |
| 找不到 MAPPING 文件 | 系统别名不匹配 | 检查 `SYSTEM_ALIAS_MAP` 配置 |
