# 词根翻译

英文只来自词根库脚本。不要凭记忆翻译。「编码」的现行词根是 `NUM` 不是 `CODE`，「指令」是 `ISTCT` 不是 `INST`。猜出来的缩写和库不一致时，以脚本为准。

## 动作

解释器只用 `/usr/bin/python3`。工作目录是仓库根。

```
/usr/bin/python3 .agents/skills/dw-field-translate/scripts/translate.py 业务日期 指令序号
```

名字很多时，一行一个，从标准输入读。用户明确要求旧词根时加 `--old`，否则用现行词根；用户明确要求机器可读格式时加 `--json`。

把脚本打印的表（或 JSON）原样给用户。不要改英文，不要把 `??` 换成自己编的缩写，不要为了「好看」改用旧词根。

旧词根差异列不是「—」时，用一句话指出现行和旧的差别。仍然采用现行词根，除非用户说了用旧的。

## 缺词

切分里的 `?`、英文里的 `??` 表示词库没有这段。指出缺的是哪一段，问要不要补。不要自己造缩写填进去。

## 解释结果时

这些规则已经做进脚本。用来向用户解释，不要自己再切一遍。

- 从左到右最长匹配。库里有整词就不再拆开。
- 英文小写，段与段用 `_`。大写列是同一结果的大写。
- 数字 0–9 映射到自己。
- 只去掉名字两端的空白。中间的空格会变成 `?`。
- 同名中文有多行时，用词库第一行。

## 更新词库

源工作簿改过之后才刷新（工作簿路径若变动，以用户实际提供的 `.xlsm` 路径为准）。不要手改 `data/roots.json`。

```
/usr/bin/python3 .agents/skills/dw-field-translate/scripts/translate.py --extract "/mnt/d/项目/企业微信/03_信达澳亚投研数据集市项目/99_过程产出文档/08_数据治理/数据仓库模型字段名_宏翻译-信达20230614.xlsm"
```
